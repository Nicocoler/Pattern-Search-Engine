# K线-布林带阶段性形态识别 开发方案

## 0. 背景与目标

现有系统已具备：每支股票的布林带（上轨 Upper / 中轨 Middle / 下轨 Lower）计算能力。

本次要新增的能力：**基于K线相对布林带三轨的位置关系，识别多阶段走势编排**（如"突破中轨→中轨上方横盘→突破上轨→回落中轨横盘"），支持：

- 阶段数量固定、顺序固定，但每阶段持续天数不限
- 多种走势编排可配置、可扩展，无需改代码即可新增形态
- 每日全市场批量扫描，输出命中股票及匹配区间

核心设计原则：**不比较图片、不比较绝对数值，只比较"K线相对布林带的位置状态"随时间演变的序列关系**。整体方案分五层：指标层 → 状态层 → 模板层 → 匹配引擎层 → 调度与输出层。

---

## 1. 整体架构

```
┌─────────────┐   ┌──────────────┐   ┌───────────────┐   ┌────────────────┐   ┌───────────────┐
│  行情/布林带  │ → │  %B 计算层    │ → │  状态离散化层   │ → │  正则模板匹配引擎 │ → │  扫描调度与输出 │
│ (已有能力)   │   │ (新增)        │   │ (新增)         │   │ (新增)          │   │ (新增)         │
└─────────────┘   └──────────────┘   └───────────────┘   └────────────────┘   └───────────────┘
```

每一层职责单一、可独立测试，方便嵌入现有项目的既有数据管道。

## 2. 第一层：%B 指标计算

### 2.1 定义

在现有布林带基础上，新增衍生指标 %B，表示收盘价在三轨中的相对位置：

```
%B = (close - lower) / (upper - lower)
```

- `%B >= 1`：触及或突破上轨
- `%B ≈ 0.5`：贴近中轨
- `%B <= 0`：触及或跌破下轨

### 2.2 实现要点

- 输入：现有布林带计算结果（upper, middle, lower）+ 收盘价序列
- 输出：新增一列 `pct_b`，与现有行情表结构对齐，按股票代码+交易日存储
- 边界处理：`upper == lower`（极端无波动行情）时，%B 记为 `NaN` 或沿用上一个有效值，避免除零

### 2.3 建议接口

```python
def calc_pct_b(close: pd.Series, upper: pd.Series, lower: pd.Series) -> pd.Series:
    """返回与输入等长的 %B 序列"""
    band_width = upper - lower
    pct_b = (close - lower) / band_width
    pct_b[band_width == 0] = np.nan
    return pct_b
```

集成点：挂在现有布林带计算函数之后，作为其下游的一个新字段，无需改动布林带本身的计算逻辑。

## 3. 第二层：状态离散化

### 3.1 分区定义（可配置）

```python
ZONE_THRESHOLDS = {
    "L":  (-float("inf"), 0.35),   # 中轨下方
    "M":  (0.35, 0.65),            # 贴中轨
    "H":  (0.65, 0.95),            # 中轨与上轨之间（过渡态）
    "U":  (0.95, float("inf")),    # 触及/突破上轨
}

def zone(pct_b: float) -> str:
    for label, (lo, hi) in ZONE_THRESHOLDS.items():
        if lo <= pct_b < hi:
            return label
    return "NA"  # NaN 或异常值
```

阈值应做成配置项（如 JSON/YAML），而非硬编码，方便后续针对不同市场/标的调优。

### 3.2 游程压缩（Run-Length Encoding）

逐日状态会有噪声抖动，先压缩连续相同状态，避免"一日游"突破干扰匹配：

```python
def compress(states: list[str]) -> list[tuple[str, int]]:
    """[('L',5), ('M',3), ('U',2), ...]"""
    groups = []
    for s in states:
        if groups and groups[-1][0] == s:
            groups[-1][1] += 1
        else:
            groups.append([s, 1])
    return [tuple(g) for g in groups]
```

### 3.3 最短持续天数过滤（去抖动）

对游程压缩结果，过滤掉持续天数小于阈值（如1-2天）的状态段，将其"吸收"进相邻状态，避免单日尖峰被误判为独立阶段：

```python
def denoise(runs: list[tuple[str, int]], min_len: int = 2) -> list[tuple[str, int]]:
    # 短于 min_len 的段与相邻段合并（简化实现：合并进前一段）
    ...
```

### 3.4 转为匹配用的字符串

匹配引擎直接使用字符串而非游程元组，更方便用正则：

```python
def state_string(states: list[str]) -> str:
    return "".join(states)  # 未压缩，用于正则的 {n,} 量词天然处理重复
```

**注意**：正则匹配直接用未压缩的逐日状态字符串即可（正则的 `M{3,}` 本身就能表达"连续至少3天"），游程压缩主要用于人工查看/调试和"最短持续天数"的预处理去噪，不必须作为正则输入的前置步骤。

## 4. 第三层：走势编排模板（可配置、可扩展）

### 4.1 设计目标

新增一种走势形态 = 新增一行配置，不改代码。

### 4.2 配置文件结构（YAML）

```yaml
patterns:
  - id: breakout_upper_pullback_mid
    name: "中轨突破-上轨突破-回落中轨横盘"
    regex: "L+M{3,}H*U+H*M{3,}"
    min_total_days: 10
    enabled: true

  - id: lower_rebound_mid_flat_retest
    name: "下轨反弹-中轨横盘-再次探底"
    regex: "U*H*M{3,}L+M{2,}L+"
    min_total_days: 8
    enabled: true
```

字段说明：

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识，用于结果关联 |
| `name` | 人类可读名称 |
| `regex` | 状态字符串上的正则表达式，量词 `+`/`*`/`{n,}` 表达"天数不限但需满足最少持续" |
| `min_total_days` | 整个形态最短总天数，用于二次过滤，避免正则命中过短的片段 |
| `enabled` | 是否启用，方便临时关闭某模板而不删除配置 |

### 4.3 正则编写规范（供后续新增模板参考）

- 每个阶段用一个字母表示核心区域状态（`L`/`M`/`H`/`U`）
- 阶段间允许过渡态用 `H*`（如从L到U之间可能经过H，不强制）
- "横盘"用重复量词表达，如 `M{3,}` 表示至少连续3天贴中轨
- 阶段顺序即正则中字母出现的顺序，天然表达"不限制天数，只要求顺序和最短持续"

## 5. 第四层：匹配引擎

### 5.1 单只股票单模板匹配

```python
import re

def find_pattern(state_str: str, pattern_cfg: dict) -> list[dict]:
    compiled = re.compile(pattern_cfg["regex"])
    results = []
    for m in compiled.finditer(state_str):
        start, end = m.span()
        if end - start < pattern_cfg.get("min_total_days", 0):
            continue
        results.append({
            "pattern_id": pattern_cfg["id"],
            "pattern_name": pattern_cfg["name"],
            "start_idx": start,
            "end_idx": end,
            "matched_states": state_str[start:end],
        })
    return results
```

`finditer` 默认不重叠匹配，如果需要允许重叠的形态（同一段行情同时被多个模板命中属正常，但同一模板内部重叠一般不需要），保持默认即可。

### 5.2 索引到实际日期

匹配结果的 `start_idx`/`end_idx` 是状态字符串里的位置，需要映射回原始交易日序列（因为状态字符串与原始行情逐日一一对应，直接用同长度的日期数组按下标取值即可）：

```python
dates = df["trade_date"].tolist()
match_start_date = dates[result["start_idx"]]
match_end_date = dates[result["end_idx"] - 1]
```

### 5.3 二次打分（可选，提升结果质量）

命中正则只是"结构上符合"，可选叠加数值维度做强度打分，用于排序展示：

- 阶段 U 内 %B 的最大值（突破幅度）
- 阶段 M 横盘阶段的 %B 标准差（横盘的"平"的程度）
- 成交量在阶段2（上涨突破）是否放大（如有成交量数据）

打分不影响是否命中，只影响多结果的排序展示优先级。

## 6. 第五层：批量调度与集成

### 6.1 每日增量扫描流程

```
收盘后行情/布林带更新完成
        │
        ▼
增量计算 %B（仅新增交易日）
        │
        ▼
更新每只股票最近N天(如120天)的状态字符串（滑动窗口，不用全量重算）
        │
        ▼
遍历 patterns.yaml 中 enabled=true 的模板
        │
        ▼
对每只股票的状态字符串跑 finditer
        │
        ▼
命中结果写入结果表 / 推送通知
```

### 6.2 建议数据结构

新增两张表（或在现有表基础上扩展字段）：

**`stock_state_daily`**（逐日状态，增量更新）

| 字段 | 说明 |
|---|---|
| stock_code | 股票代码 |
| trade_date | 交易日 |
| pct_b | %B 值 |
| zone | 离散状态（L/M/H/U） |

**`pattern_match_result`**（命中结果，每次扫描追加）

| 字段 | 说明 |
|---|---|
| stock_code | 股票代码 |
| pattern_id | 命中的模板ID |
| start_date / end_date | 匹配区间 |
| matched_states | 匹配到的状态字符串（便于人工复核） |
| score | 可选的二次打分 |
| scan_date | 本次扫描日期（用于区分"新发现"还是"历史已有"） |

### 6.3 与现有项目的集成方式

- 若现有布林带计算是批处理任务（如每日收盘后跑一次），本功能作为该任务的**下游新增步骤**接入，不改动原有布林带计算逻辑
- %B 计算和状态离散化可以做成无状态的纯函数模块，输入现有布林带输出即可，方便单元测试
- 状态字符串按股票维度做滑动窗口维护（如只保留最近120个交易日），避免每天全量重算历史

## 7. 测试与验证方案

### 7.1 单元测试

- %B 计算：构造已知 close/upper/lower 数值，验证输出精确匹配
- 状态离散化：边界值测试（如 %B 恰好等于 0.35、0.65、0.95 时的分区归属）
- 正则匹配：构造"应该命中"和"不应该命中"的手工状态字符串样例（如序列反过来、中间缺失某阶段），验证 finditer 结果正确

### 7.2 历史回测验证

- 选取几只你已知历史上确实出现过目标形态的股票，跑一遍匹配引擎，确认能否正确命中，起止日期是否符合预期
- 反向验证：选取明显不符合形态的股票/时间段，确认不会误命中（重点检查阈值和最短天数参数是否过于宽松）

### 7.3 参数调优建议

以下参数建议做成可调配置，通过历史回测对比不同取值的命中数量和准确率：

- 分区阈值（0.35 / 0.65 / 0.95 这几个边界）
- 去噪最短持续天数（min_len）
- 模板中各阶段的最短重复次数（如 `M{3,}` 中的 3）

---

## 8. 性能与规模考量

- 全市场股票数量通常在千到万级别，每只股票状态字符串长度控制在百级（如120天窗口），单模板 `finditer` 对百字符串的匹配是毫秒级操作，全市场全模板扫描预计在秒级到分钟级，可接受
- 若模板数量后续增长较多（几十个以上），可考虑：
  - 用多进程/多线程按股票分片并行扫描
  - 对状态字符串做缓存，仅当当天状态发生变化（新增交易日或历史状态被修正）时才重新扫描该股票

---

## 9. 实施步骤建议（里程碑）

1. **第一阶段**：实现 %B 计算 + 状态离散化，输出到 `stock_state_daily` 表，人工抽查几只股票的状态序列是否符合预期
2. **第二阶段**：实现正则匹配引擎 + `patterns.yaml` 配置加载，跑通1-2个模板的历史回测
3. **第三阶段**：接入每日调度流程，实现增量更新与结果落库
4. **第四阶段（可选）**：叠加二次打分维度、结果展示界面（如复用现有股票详情页展示布林带+高亮匹配区间）

---

## 10. 后续可扩展方向

- 如果未来需要表达"阶段涨幅""成交量放大"等正则无法表达的约束，可将匹配引擎从纯正则升级为**带条件的有限状态机（FSM）**：每个状态转移绑定一个校验函数（不仅判断zone，还可判断斜率、成交量等），配置结构可保持类似（仍是一份"编排定义"配置表），只是执行引擎从 `re.finditer` 换成自定义状态转移遍历
- 可考虑把"红绿柱方向"（阳线/阴线）编码进状态字母的后缀，进一步细化形态描述（如 `U+` 表示突破上轨且当日收阳）
