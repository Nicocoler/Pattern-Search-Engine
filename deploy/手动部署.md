# 手动部署（阿里云 /home/deploy/PSE）

日常更新代码、重启容器用本文。完整首次装机见 `docs/18_阿里云Docker部署.md`。

## 速查

```bash
# 推荐：SSH 登录后，用 deploy 用户一键部署（拉代码 + build + 重启）
su - deploy -c 'cd /home/deploy/PSE && bash scripts/deploy.sh'
```

```bash
# 若 git pull 冲突（见下文），先对齐再部署
su - deploy -c 'cd /home/deploy/PSE && git fetch origin main && git reset --hard origin/main && bash scripts/deploy.sh'
```

## 前提

- 代码目录：`/home/deploy/PSE`
- 部署用户：`deploy`（已加入 `docker` 组）
- 服务器上已有 `.env`（**不会被 git 覆盖**，首次从 `.env.example` 复制）
- 不要用 **root** 直接跑 `scripts/deploy.sh`（见「常见问题」）

## 方式一：服务器 SSH 手动部署（推荐）

### 1. 切到 deploy 用户并拉代码

```bash
su - deploy
cd /home/deploy/PSE
bash scripts/deploy.sh
```

`deploy.sh` 会依次执行：

1. 检查 `.env` 是否存在
2. `git fetch` + `checkout main` + `pull --ff-only`（拉取 GitHub `main`）
3. `docker compose build`
4. `docker compose up -d --remove-orphans`
5. 打印 `docker compose ps`

### 2. 一条命令（root 登录时）

```bash
su - deploy -c 'cd /home/deploy/PSE && bash scripts/deploy.sh'
```

### 3. 代码已是最新，只重建容器

例如刚执行过 `git reset --hard`，或确定磁盘文件无需再 pull：

```bash
su - deploy -c 'cd /home/deploy/PSE && SKIP_GIT_PULL=1 bash scripts/deploy.sh'
```

| 环境变量 | 含义 |
|----------|------|
| 默认 / `SKIP_GIT_PULL=0` | 先 `git pull`，再 compose build/up |
| `SKIP_GIT_PULL=1` | 跳过 git，仅 compose build/up |

### 4. 验收

```bash
curl -sS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/docs   # 期望 200
curl -sS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/      # 期望 200
docker compose ps
```

## 方式二：GitHub Actions 手动触发

推送 `main` **不会**自动部署；需要时在 GitHub 操作：

1. 仓库 → **Actions** → **Deploy to Aliyun**
2. **Run workflow** → 选分支（通常 `main`）→ **Run workflow**

流程：SSH 到服务器 → 在 `/home/deploy/PSE` 执行 `bash scripts/deploy.sh`（`git pull` + compose build/up，与方式一相同）。

所需 Secrets：`DEPLOY_HOST`、`DEPLOY_USER`、`DEPLOY_SSH_KEY`、可选 `DEPLOY_PORT`。

## 常见问题

### 1. `fatal: detected dubious ownership in repository`

**原因**：用 root 在 `/home/deploy/PSE` 里执行 git，目录属主是 `deploy`，Git 2.35+ 会拒绝。

**处理**：改用 `deploy` 用户（见上文速查），不要对 root 执行 `git config safe.directory`。

### 2. `Your local changes would be overwritten by merge`

**原因**：服务器上有未提交的本地修改（例如曾在服务器上直接改过跟踪文件），`git pull` 会覆盖这些文件因而失败。

**处理**：以远端 `main` 为准强制对齐，再部署：

```bash
su - deploy -c 'cd /home/deploy/PSE && git fetch origin main && git reset --hard origin/main && bash scripts/deploy.sh'
```

**注意**：`reset --hard` 会丢弃服务器上相对当前 commit 的 git 跟踪差异；`.env` 不在 git 里，不受影响。

### 3. `ERROR: missing .env`

```bash
su - deploy
cd /home/deploy/PSE
cp .env.example .env
# 编辑 DATABASE_URL 等
bash scripts/deploy.sh
```

### 4. backend 连不上 PostgreSQL

检查 `.env` 里 `DATABASE_URL`、PG 是否监听、Docker 能否访问宿主机 `5432`。详见 `docs/18_阿里云Docker部署.md`。
